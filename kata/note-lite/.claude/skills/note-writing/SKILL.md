# note 記事を1本書く（Lite 版）

元のキット（`addons/_original/`）の9ステップのうち、**記事の中身を作る部分**をそのまま残し、
有料の API（Jina・画像生成）とブラウザの自動操作（note への自動入稿）を外したものです。

```
[Step 0] 起動チェック（人格が設定済みか・テーマがあるか）
[Step 1] テーマ決定（themes.md の上から最初の未着手）
[Step 2] 競合分析 ★（Web 検索と Web 読み込みで上位記事を読む → 比較表 → 勝ち筋）
[Step 3] 記事生成（5つの構成パターンから選ぶ → persona.md の人格で書く）
[Step 4] ファクトチェック ★（事実を1つずつ一次情報と突き合わせる）
[Step 5] 仕上げ（article.md とプレビューを output/ にそろえる）
[Step 6] 人に渡す → 人が note に貼って公開 → 「公開した」で themes.md を更新
```

★ = 省略禁止

## コマンドの実行

- Python の呼び方: Windows は `py`、Mac は `python3`（以下 `PY`）
- **Bash ツール**で、`PY .claude/skills/note-writing/scripts/...` の相対パスのまま実行する。Windows でも PowerShell ツールは使わない

---

## Step 0: 起動チェック

```bash
PY .claude/skills/note-writing/scripts/check_persona.py
```

失敗したら止める。「persona.md を一緒に埋めて」と頼めば対話で埋められる、と伝える
（埋めるときは質問しながら。**本人が言っていない経歴・体験を作らない**）。

`themes.md` に `- [ ]` のテーマが無ければ止める。テーマを足すのは人の仕事。

## Step 1: テーマ決定

`themes.md` の「キュー」の上から最初の `- [ ]` を1つ選ぶ。メインKW・切り口・想定読者・想定文字数を読む。
同じテーマを連続で書かない（「完了済み」を見る）。

## Step 2: 競合分析（★ 省略禁止）

1. **WebSearch ツール**でメインKWを検索し、上位の記事 URL を5つ控える
2. 公式以外の上位記事を**3本以上**、**WebFetch ツール**で全文読む
3. 比較表を作る（この表がないと次に進めない）

| 項目 | 競合 A | 競合 B | 競合 C | この記事（計画） |
|---|---|---|---|---|
| タイトル | | | | |
| 文字数（おおよそ） | | | | |
| 見出しの数 | | | | |
| 具体性（実例・固有名詞） | | | | |
| 独自の視点 | | | | |
| 弱点 | | | | |

4. **勝ち筋を3つ以上**言葉にし、Step 3 の構成に反映する

ルール:
- **本文に競合への言及を入れない**（「他のサイトでは」「どこよりも」「網羅的に」は使わない）
- 比較表は `output/<スラッグ>/research.md` に残す（あとで人が見返せるように）

## Step 3: 記事生成

`references/article-template.md`（記事の型）・`references/persona.md`（人格）・`references/title-guide.md`（題名）を読む。

構成パターンを5つから1つ選ぶ（前回と被らせない）:

| パターン | 内容 | 向くテーマ |
|---|---|---|
| 羅列型 | 要素を見出しで並べる | 選択肢・商品の比較 |
| 時系列型 | 時間の順に展開 | 手順・ストーリー |
| Q&A 型 | 読者の質問に答える | 初心者向けの解説 |
| 数値シミュレーション型 | 数字から逆算 | 費用・効果の試算 |
| 難易度順 | 簡単 → 難しい | 入門ガイド |

禁止表現（1つでも入ったら書き直し）:

```
〜することができます    →  〜できます
〜が可能です            →  〜できます
幅広く／網羅的に        →  具体的に書く
他のサイトでは／どこよりも  →  そもそも言及しない
一助となれば            →  そもそも書かない
ぜひ参考にしてください  →  別の締め方
```

- 文字数 800〜1,500字、大見出し（`##`）3〜6個
- **`persona.md` の「体験として書いてよいこと」に無い体験を書かない**
- 1行目は `# タイトル`
- `output/<スラッグ>/article.md` に保存する（スラッグは半角英数字とハイフン）

## Step 4: ファクトチェック（★ 省略禁止）

1. 記事中の事実（数値・期限・固有名詞・条件）を**すべて**書き出す
2. 1つずつ、**一次情報**（公式サイト・発表元）を WebFetch で読んで突き合わせる。まとめサイトは根拠にしない

| 判定 | 対応 |
|---|---|
| 一致 | そのまま |
| 数値が古い・違う | 一次情報に合わせて直す |
| 略称・通称 | 正式名称に直す |
| 終了・廃止 | その項目を記事から外す |
| 一次情報が見つからない | **その事実を記事から外す** |

結果（事実・出典 URL・判定）を `output/<スラッグ>/factcheck.md` に表で残す。

## Step 5: 仕上げ

```bash
PY .claude/skills/note-writing/scripts/note-preview.py output/<スラッグ>/article.md
```

- `output/<スラッグ>/preview.html` ができ、本文の文字数が出る。800字未満なら書き足す
- `references/article-template.md` の品質チェックを全項目確かめる

## Step 6: 人に渡す

短く伝える:

- 題名と文字数、選んだ構成パターン、勝ち筋3つ
- ファクトチェックの結果（直した・外した事実があれば必ず）
- 渡すファイル: `article.md`（貼る本文）・`preview.html`（見た目の確認用）・`research.md`・`factcheck.md`
- note への貼り方: `preview.html` をブラウザで開いて読み、note の編集画面に本文を貼る。見出しは note の「見出し」ボタンで付ける
- 公開したら「公開した <URL>」と伝えてもらう

「公開した」と言われたら、`themes.md` のそのテーマを `- [x] **テーマ名** — YYYY-MM-DD / URL` にして「完了済み」へ移す。
**人が言う前に themes.md を完了にしない。**

## ハードルール

1. 1回で書く記事は1本まで
2. 競合分析なしに書き始めない
3. 公開前に必ずファクトチェック。確かめられない事実は書かない
4. `persona.md` に無い経歴・体験を書かない
5. 本文に競合への言及を入れない
6. 生の URL を貼らない（テキストリンクで）
7. 800字未満の記事は渡さない
8. themes.md に無いテーマで勝手に書かない
