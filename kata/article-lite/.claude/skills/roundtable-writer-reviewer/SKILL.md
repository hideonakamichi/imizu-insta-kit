# おしゃべりコーナーの執筆・査読手順

対象テーブル: **roundtables**。URL は `/roundtable/{slug}`。
制度解説では扱えない「暮らしのリアル」を**当事者同士**が語る企画。テーマ例: 結婚の形 (事実婚・週末婚)、離婚後の過程、子どもへの説明、戸籍や名字。

## 3コンテンツの違い (★混同禁止★)

| | 制度記事 (supports) | 用語集 (glossary) | **おしゃべり (roundtables)** |
|---|---|---|---|
| 主役 | 解説役の解説 | 解説役の解説 | **当事者2人の対話** |
| 目的 | 制度を正確に伝える | 用語を分かりやすく | **選択肢と気持ちの整理** |
| 文字数 | 10,000字以上 | 1,200〜3,000字 | **4,000〜6,000字** |
| 図解 | 2枚必須 | 不要 | 不要 |
| 解説役 (`explainer`) | 全編 | 全編 | **末尾のみ (500〜800字)** |
| チェック | 25項目 + E01〜E19 | 13項目 | **15項目 (うち6が倫理)** |

## 登場人物

★★★ **執筆前に必ず `config/persona.json` を Read すること。** ★★★
（無ければ `config/persona.example.json`）名前・年齢・立場・口調はすべてそこが正本。
**この SKILL に名前をハードコードしないこと。**

このコーナーで使う 3 つの役割:

| 役割 (`id`) | 位置づけ | 吹き出し |
|---|---|---|
| **質問役** (`questioner`) | 当事者のひとり。制度記事にも出ている読者代表 | 左・白バブル |
| **相手役** (`peer`) | もうひとりの当事者。**違う選択をしている人** | 左・薄い色のバブル |
| **解説役** (`explainer`) | 専門家。**末尾の制度補足パートのみ** | 右・緑バブル |

★相手役は「対立する人」ではなく「並列する人」。どちらの生き方も肯定も否定もしない。★
ここを外すと、当事者を傷つける記事になります (倫理チェック項目が 6 つあるのはこのため)。

## 構成テンプレート

1. 導入 (互いの状況を紹介し合う自然な入り)
2. 一方が「その選択をした理由」(押し付けず、自分の場合はこうだった)
3. 実際どう違うか (**暮らしの実感レベル**で。制度上の断定はしない)
4. 子どもへの説明 (学校での場面など)
5. 迷っている人へ (**どちらが良いとは言わない**)
6. **藤井先生の制度補足** (H2 で明確に区切る。関連制度記事・用語集へリンク)

## ★絶対に守ること (YMYL + 倫理)

- **どちらの生き方も推奨・否定しない**。「〜すべき」「〜した方がいい」を使わない
- **当事者に制度を断定させない**。「私が窓口で言われたのは」「制度は変わるから確認して」の形にヘッジする
- **不安を煽らない**。事実婚=損 / 離婚=正解 のような構図にしない
- 特定の個人が浮かぶ具体的すぎるエピソードは書かない
- 冒頭または末尾に「実際にあるお悩みをもとにした**架空の対話**です」の注記
- 子どもを不憫に見せる書き方・子どもの発言を過度にドラマチックにしない
- 末尾の免責 (時点・個別事情や自治体で異なる・窓口へ相談)

## ★段落ごとに話者タグを付ける (2026-07-25 追加・重要)

`site/lib/markdown.js` の `rehypeDialogue` は**段落 (空行区切り) 単位**で先頭が `**名前**:` かを判定する。
つまり**同じ人が続けて話す場合も、段落ごとに話者タグを書く必要がある**。タグのない段落は吹き出しに入らず「地の文」として表示される。

```markdown
**藤井**: 一段落目のテキスト。

**藤井**: 二段落目も必ずタグを付ける。← これを忘れると地の文になる
```

執筆時も査読時も、**必ず curl でレンダリング結果を確認**し、吹き出しの数と話者の発言数が一致するか検証すること。

## 査読基準 (15項目)

### A. 形式 (4項目)
1. 話者は登場人物のみ。記法 `**名前**:` で統一
2. 解説役は**末尾の制度補足パートのみ**に登場 (対話の途中で割り込んでいない)
3. 全角コロン・HH:MM・H1 なし、`<mark>` と `:::` の開閉一致
4. 文字数 4,000〜6,000字

### B. 倫理・安全性 (★最重要・6項目★)
5. どちらの生き方も推奨・否定していない
6. 当事者が制度を断定していない (ヘッジされている)
7. 不安を煽っていない
8. 架空の対話であることの注記がある
9. 個人が特定されるような具体的すぎるエピソードがない
10. 子どもの描写が適切

### C. 制度補足パート (3項目)
11. 制度の記述が正確 (一次ソースを WebFetch で再照合)
12. 「自治体が実態を総合判断」「自己判断せず窓口へ」が入っている
13. 断定と例外のバランス (極端な誤読を招かない)

### D. リンク・末尾 (2項目)
14. 関連する `/support/{id}` `/words/{slug}` へのリンクがあり、リンク先が実在する
15. 末尾に免責がある

### 対応方針
- フォーマット系 (話者タグ漏れ・全角コロン等) → **自分で修正して DB 保存**
- **倫理・安全性 (B) に問題 → 必ず差し戻し** (書き直しが必要)
- 制度補足の事実誤認 → 差し戻し
- 合格時は `research_notes.reviewer_verifications` に追記

## DB 操作

```bash
bash scripts/supabase-query.sh select roundtables "slug=eq.{slug}&select=*"
bash scripts/supabase-query.sh update roundtables @/tmp/payload.json "slug=eq.{slug}"
```
payload: `article_md` / `research_notes` / `published_at` / `related_support_ids` / `related_glossary_slugs`
