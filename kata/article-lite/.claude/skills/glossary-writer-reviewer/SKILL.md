# 用語集の執筆・査読手順

対象テーブル: **glossary** (制度記事の supports とは別)。URL は `/words/{slug}`。
読者は制度用語が苦手なひとり親。「そもそも扶養って何？」レベルから説明する。

## 制度記事との違い (★混同禁止★)

| | 制度記事 (supports) | 用語集 (glossary) |
|---|---|---|
| 文字数 | 10,000字以上 | **1,200〜3,000字** |
| 図解画像 | 2枚以上必須 | **不要** |
| チェック項目 | 25項目 + E01〜E19 | **13項目 (下記)** |
| 装飾 | pointbox/warning/steps 全部使う | `<mark>` と `:::pointbox` を控えめに。steps 不要 |
| FAQ | 5問程度 | **2〜3問** |
| 内容 | 制度の網羅的解説 | 用語の意味 + 生活実感の具体例 |

## 執筆ルール (ライター)

- **冒頭に一言定義** (`short_def` カラム・60字以内・小学校高学年でも読める言葉)
- **質問役 (`questioner`) が「わかってない前提」で聞く**。例: 「扶養って、養ってもらってる人ってことですか？」
- **数字より具体例中心**。「パート年収130万円の壁ってこれのこと」など生活実感で
- 話者は**質問役 / 解説役**の 2 人。★名前・口調は `config/persona.json` (無ければ `config/persona.example.json`) を Read して従うこと。ここにハードコードしない★
- 関連する制度記事に `/support/{id}` でリンクし、`related_support_ids` にも入れる
- 末尾に短い免責 (時点 + 窓口確認を促す一文)
- 数字を書くときは一次ソース (国税庁・こども家庭庁・自治体公式) を WebFetch で照合し research_notes に quote を残す

### ★年分・年度の表記ルール (2026-07-25 追加)

- 所得税は「令和{N}年**分**」、住民税は「令和{N}年**度**分」。両者を混同しない
- **適用開始年を必ず一次ソースで確認する** (例: 扶養親族の所得要件58万円は「令和7年分から適用」であり「令和8年分」ではない)
- 改正が続いている項目 (年収の壁など) は、具体額を書かずにぼかす判断も可

## 査読ルール (レビュアー) — 13項目

### A. 形式 (5項目)
1. **質問役の発言**で始まる / 話者は質問役・解説役のみ / 話者逆転なし
2. 全角コロン `：` が話者記法にない / HH:MM 形式なし
3. `<mark>` と `:::` の開閉一致
4. H1 (`# `) を含まない
5. 文字数 1,200〜3,000字 (3,000字超は冗長として指摘)

### B. 内容 (5項目)
6. **やさしさ**: 制度用語をいきなり使わない。専門用語には直後に噛み砕きがある
7. **具体例**: 生活実感のある例が入っている
8. **short_def**: 60字以内 / 平易 / 本文と矛盾しない
9. **数字の正確性**: research_notes の quote と対応し、一次ソースに基づく。**年分/年度ラベルも照合する**
10. **内部リンク**: `/support/{id}` の ID が DB に実在 / `/words/{slug}` が登録済みの語

### C. デリケートな配慮 (3項目)
11. **受給資格に関わる語** (事実婚等): 「自己判断させない」書き方か (窓口相談で締める) / 過度に不安にさせないか
12. **有利不利の誘導をしない** (例: 世帯分離すれば手当が有利、という書き方をしない。実態判断であることを明示)
13. **免責**: 末尾に時点 + 窓口確認を促す一文がある

### 対応方針
- フォーマット系・軽微な表記誤り (年分ラベル等) → **自分で修正して DB 保存**
- 数値の誤り・危険な断定・構造的欠落 → **差し戻し**
- 合格時は `research_notes.reviewer_verifications` に検証履歴を追記

## DB 操作

```bash
# 一覧
bash scripts/supabase-query.sh select glossary "select=id,slug,term,short_def,article_md&order=sort_order"

# 保存 (本文が大きいので @file 方式)
bash scripts/supabase-query.sh update glossary @/tmp/payload.json "slug=eq.fuyou"
```

payload に含めるもの: `article_md` / `short_def` (更新時) / `research_notes` / `related_support_ids`

## 表示確認

```bash
curl -s -o /dev/null -w '%{http_code}' http://localhost:3000/words/{slug}
```
※ `site/lib/supabase.js` の revalidate=300 により、DB 更新のページ反映は最大5分遅延する
