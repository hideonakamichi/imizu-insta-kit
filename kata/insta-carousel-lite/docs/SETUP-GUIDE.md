# セットアップと運用のガイド

README.md の「はじめかた」を、画面の操作まで含めて詳しく書いたものです。

> **動作確認の状況**: Windows 11 で確認済み（Python 3.12）。Mac は確認中です。

---

## 1. 全体の流れ

| 手順 | やること | かかる時間の目安 |
|---|---|---|
| 2 | Python を入れる | 5分 |
| 3 | Claude Code でフォルダを開く | 5分 |
| 4 | ライブラリを入れる | 2分 |
| 5 | 初期設定（brand-setup） | 30〜60分（文章を一緒に書く時間を含む） |
| 6 | 1本作る | フル版では10〜20分 |
| 7 | スマホに送って投稿する | 5分 |

外部サービスの登録やキーの取得はありません。

---

## 2. Python を入れる

すでに入っているかは、ターミナルで次を打つと分かります。`Python 3.10` 以上が出れば、この手順は飛ばせます。

| OS | 確かめるコマンド |
|---|---|
| Windows | `py --version` |
| Mac | `python3 --version` |

### Windows

1. https://www.python.org/downloads/ から、最新版のインストーラーを取ってきて実行する
2. 最初の画面で **「Add python.exe to PATH」にチェックを入れて** から「Install Now」を押す
3. ターミナルを開き直して `py --version` を確かめる

Windows では、`python3` と打つと Microsoft Store が開くことがあります。これは Python の本体ではなく
Store への案内なので、このキットでは使いません。Windows では `py` を使います。

### Mac

`python3 --version` を打って、入っていなければ「コマンドライン・デベロッパ・ツール」を入れるかを聞かれます。
「インストール」を押せば Python 3 も入ります。

---

## 3. Claude Code でフォルダを開く

1. Claude Code を入れる（https://claude.com/claude-code ）。VS Code の拡張機能でも、ターミナル版でも構いません
2. このフォルダ（`insta-carousel-lite`）を開く
3. **「このフォルダを信頼しますか」と聞かれたら承認する。** 承認しないと、`.claude/settings.json` に書いた
   「このコマンドは確認なしで実行してよい」という許可が効かず、コマンドのたびに確認を求められます

---

## 4. ライブラリを入れる

このフォルダでターミナルを開いて実行します。入るのは、画像を描く Pillow と、設定ファイルを読む PyYAML の2つだけです。

| OS | コマンド |
|---|---|
| Windows | `py -m pip install -r requirements.txt` |
| Mac | `python3 -m pip install -r requirements.txt` |

Claude Code に「requirements.txt のライブラリを入れて」と頼んでも構いません。

---

## 5. 初期設定（brand-setup）

Claude Code に次のように頼みます。

```
brand-setup スキルで設定して。発信したいのは〇〇で、売りたいのは△△
```

2〜3問ずつ質問されるので、答えていきます。聞かれるのは、次のようなことです。

- 誰に届けたいか（「30代女性」のような属性ではなく、「今どんな状況にいる人か」で答えると投稿がぶれません）
- その人が困っていること、この発信でどうなってほしいか
- 売りたいもの、誘導先
- 言ってはいけないこと、雰囲気、色

答え終わると `config/brand.yaml` が埋まり、投稿の根拠になる文章（`content/sources/*.md`）の最初の数本も一緒にできます。
文章がまだ無い人は、インタビュー形式で一緒に書きます。**書かれた文章は必ず読んで、事実が合っているかを確かめてください。**

設定が済んだかは、次のどちらかで確かめられます。

- Claude Code に「brand.yaml の設定をチェックして」と頼む
- ターミナルで `py .claude/skills/shared/scripts/check_brand.py`（Mac は `python3`）を実行する

`[ok] brand.yaml は設定済みです` と出れば完了です。

---

## 6. 1本作る

```
カルーセル作って
```

途中で、ネタ選び・構成・描画・評価の様子が流れていきます。終わると、次のように報告されます。

- 投稿用フォルダの場所（`output/<日付>_<テーマ>/post/`）
- キャプションの冒頭
- 投稿のしかた

評価で2回通らなかったときは、投稿用フォルダを作らずに止まり、何が通らなかったかが報告されます。
それまでの生成物は `output/` に残っているので、見返して、ネタ元の文章や `brand.yaml` を直してからもう一度作れます。

特定の節を使いたいときは「このネタで」と伝えます（例:「机まわりの手順2で作って」）。

---

## 7. スマホへの送り方と投稿

`post/` の中の `01.png`〜 と `caption.txt` をスマホに送ります。送り方は何でも構いません。

| 方法 | 向いている人 | 注意 |
|---|---|---|
| クラウドのフォルダ（OneDrive・Google ドライブ・iCloud Drive） | キットをクラウドの同期フォルダに置いている人 | スマホのアプリから画像を「保存」してカメラロールに入れる |
| AirDrop | Mac と iPhone の人 | いちばん手軽 |
| 自分宛てにメッセージで送る | 上のどれも使っていない人 | LINE で送るときは「オリジナル画質」にする。画質が落ちると文字がにじむ |

投稿のしかた:

1. Instagram で「新しい投稿」を開き、複数選択にする
2. 画像を **`01` から順に** 選ぶ（この順番がスライドの並びです）
3. `caption.txt` の中身をコピーして、キャプション欄に貼る

**投稿しなかったとき**は、Claude Code に「これは没」と伝えます。そのネタが作成履歴から外れて、また選ばれるようになります。
伝えないと、その節は14日間選ばれません（作った時点で「使用済み」と記録しているためです）。

## 8. モデルの選び方

このキットでは、4つの役割がそれぞれ AI モデルを使います。モデルは、賢いほど結果が安定し、そのぶん利用量が増えます。

| 役割 | 何をするか | 切り替える場所 |
|---|---|---|
| 司令塔 | 全体の進行と、カルーセルの構成（どの枚に何を書くか）の設計 | Claude Code の `/model` |
| ネタ選び | 索引と履歴を照らし合わせて、今回使う節を1つ選ぶ | `config/runtime.yaml` の `models.theme_picker` |
| キャプション | 投稿の本文とハッシュタグを書く | `config/runtime.yaml` の `models.caption_writer` |
| 評価 | スライドとキャプションを合否判定する | `config/runtime.yaml` の `models.evaluator` |

`runtime.yaml` に書ける値は `opus` / `sonnet` / `haiku` です。Opus がいちばん賢く、Sonnet は速くて利用量が少なく、
Haiku はさらに軽いモデルです。

### おすすめの組み合わせ

| | 司令塔 | ネタ選び | キャプション | 評価 | メリット | デメリット |
|---|---|---|---|---|---|---|
| **品質優先（既定）** | Opus | Sonnet | Sonnet | Opus | フル版で実績のある組み合わせ。構成も評価もいちばん安定する | 利用量がいちばん多い |
| 節約 | Sonnet | Sonnet | Sonnet | Opus | 司令塔は1回の中でずっと動くので、ここを下げると利用量がいちばん減る。評価の厳しさは保てる | 構成を設計するのは司令塔なので、構成の質が下がると評価で差し戻される回数が増え、かえって利用量がかさむことがある |
| 最安 | Sonnet | Haiku | Sonnet | Sonnet | 利用量がいちばん少ない | 評価が甘くなり、悪い投稿を見逃しやすい。投稿前に自分の目で見ることが前提になる |

どの組み合わせでも、実際の利用量はまだ測っていません。上の比較は、役割の重さから見た目安です。

### 迷ったときの考え方

- **評価役は最後まで下げない。** 評価役は「悪い投稿を出さない」最後の砦です。下げると、見逃しは投稿してから気づくことになります
- **利用量を減らしたいときは、まず司令塔を下げる。** 司令塔の利用量がいちばん大きいためです
- **ネタ選びは Haiku でも足りることが多い。** 索引と履歴を照らし合わせるだけの仕事だからです
- 契約しているプランで、どのモデルがどれだけ使えるかは、各自で確かめてください

## 9. OS の切り替え

ふつうは何もしなくて構いません。`config/runtime.yaml` の `os: auto` のままなら、
Claude Code が動いている OS に合わせて Python の呼び方（Windows: `py` / Mac: `python3`）が決まります。

| うまくいかないとき | 直し方 |
|---|---|
| Windows で `py` が見つからないと言われる | `python_command: "python"` にする |
| Python を複数入れていて、別のものを使いたい | `python_command` に使いたい Python の場所を書く（例 `"C:/Python312/python.exe"`） |

スライドの書体はキットに同梱しているので（`assets/fonts/`）、OS が違っても同じ見た目になります。

## 10. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| コマンドのたびに「実行してよいか」と聞かれる | フォルダを信頼していない。Claude Code を開き直して承認する。承認済みなら、コマンドが絶対パスになっていないかを見る（許可は `py .claude/skills/...` の相対パスで登録してある） |
| Windows で `python3` と打つと Microsoft Store が開く | Windows では `py` を使う。`config/runtime.yaml` の `os` が `auto` か `windows` になっているか確かめる |
| エラーの日本語が「�」のように化ける | PowerShell で実行した。スクリプトの出力は UTF-8 なので、Bash（Git Bash）で実行する |
| 「描画用フォントが見つかりません」 | `assets/fonts/` の書体ファイルが無い。`assets/fonts/README.md` の入手先から取り直す |
| 「brand.yaml の設定が終わっていないため、投稿を作りません」 | 雛形の値が残っている。表示された項目を直すか、「brand-setup スキルで設定して」と頼む |
| 「ネタの索引がありません」 | `content/sources/` に文章が無いか、どの節も200字未満。`_` で始まるファイルと README.md はネタにならない |
| 表紙やまとめに、途中で切れた記事名が出る | タイトルが13字を超えている。文章の先頭の `short_title` か、`brand.yaml` の `content_sources.short_titles` に短い名前を書く |
| 同じネタ元の話ばかり出る | ネタ元の文章が1〜2本しかない。文章を足す |
| 評価で何度も止まる | 多いのは、ネタ元の文章が薄い（根拠にできる具体が少ない）か、トーンの設定と文章が噛み合っていないか。止まったときの報告にある不合格の理由を見て直す |

## 11. 慣れてきたら（追加パック）

`addons/` に、Lite 版で外した機能を置いてあります。どれも**まだ Mac 専用**で、外部サービスの登録が必要です。

| パック | できること | 要るもの |
|---|---|---|
| `addons/auto-post/` | Instagram への自動投稿 | Meta for Developers・Cloudflare R2・Discord |
| `addons/reel/` | 縦型動画（リール）の生成 | Grok（SuperGrok か X Premium+）・Fish Audio・ffmpeg |
| `addons/schedule/` | 決まった時刻の自動実行・週次点検 | 常時起動の Mac（launchd） |

足し方は、それぞれの `README.md` にあります。
