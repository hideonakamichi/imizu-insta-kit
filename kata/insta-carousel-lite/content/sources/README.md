# ネタ元（投稿の根拠にする文章）の置き場所

ここに Markdown を置くと、`## 見出し` の単位で1つずつ「紹介ネタ」になります。
投稿（カルーセル・キャプション）に書かれる事実は、**選ばれた1節に書いてあることだけ**です。
AI が自分の知識で話を足すことは evaluator が不合格にします。だから、ここに置く文章の質が
そのまま投稿の質になります。

## 何を置けばいいか

自分で書いた（または内容に責任を持てる）文章なら何でも構いません。

・ブログやnoteの記事（下書きでもよい）
・よく聞かれる質問と、その答え
・商品・サービスの説明、使い方の手順
・講座やセミナーの台本、配布資料の文章
・自分の経験から言える注意点・失敗談

他人の文章の転載は置かないでください（そのまま投稿の根拠に使われます）。

## 書式

```markdown
---
title: 在宅ワークの机まわりを整える3つの手順
short_title: 机まわりの整え方
url: https://example.com/blog/desk
updated: 2026-09-01
sources:
  - 総務省「令和5年通信利用動向調査」
---

# 在宅ワークの机まわりを整える3つの手順

導入の文章（ここはネタになりません。全体の前提を書く場所）。

## 手順1 机の上に置く物を3つに絞る

この見出しの下が1つのネタになります。200字以上書いてください。
具体的な数字・手順・理由・例が入っているほど、投稿の中身が濃くなります。

## 手順2 …
```

・先頭の `---` で囲んだ部分（front matter）は省略できます。省略したら `# タイトル` が題名になります
・`short_title` は画面に出す名前で **13字以内**。省略するとタイトルの先頭13字になり、
  途中で切れた名前が出ることがあります（`config/brand.yaml` の `content_sources.short_titles` でも指定可）
・`sources` は根拠にした一次資料の名前。投稿で資料名に触れるときは、この表記どおりに書かれます
・1節が **200字未満** だとネタになりません（1投稿ぶんの根拠として薄すぎるため）
・`**強調**` した箇所は「紹介の核」として扱われます
・ファイル名（拡張子を除く）は半角英数字とハイフンにしてください。出力フォルダ名などに使われます
・`README.md` と、`_` で始まるファイルはネタになりません（下書きや見本は `_` を付けて置けます）

## 反映の確認

```bash
py .claude/skills/shared/scripts/build_article_index.py --check
```

（Mac は `py` を `python3` に読み替えます。Claude Code に「ネタの件数を確認して」と頼んでも同じです）

件数（`units`）が増えていれば取り込めています。実際の一覧は、次の起動のあとで
`content/themes.md` のストック欄に出ます（手で編集しても次の起動で上書きされます）。

## 同じネタはいつ再登場するか

`theme-picker` は直近14日以内に使った節を避けます。週3投稿なら6節、1日1投稿なら15節以上あると、
同じ話の繰り返しを避けられます。選べる節が尽きると、ネタ選びの役が「ネタが尽きかけている」と知らせます。
