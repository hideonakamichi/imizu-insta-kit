# Instagram API エラーコード表

`ig_post.py` / `refresh_token.py`（いずれも `graph.instagram.com` を使用）が返すエラーの
`error.code` を見て、オーケストレーターがとるべき対応を判断するための一覧。
`error.error_subcode` も参考にする。

| code | 意味 | 対応 |
|---|---|---|
| 190（`refresh_access_token`呼び出し時、message="Failed to decode"） | トークンが更新対象として未成熟（発行/前回更新から24時間未満）である可能性が高い | リトライしない。60日の有効期限内であれば投稿自体は継続できるので、次回の点検（週次）まで待つ。24時間以上経過してから再度手動実行して切り分けてもよい |
| 190（上記以外の文脈） | アクセストークン失効・無効 | リトライしない。失敗として中止しDiscordで緊急通知（Meta developer consoleからの手動再生成が必要な可能性） |
| 4 | APIレート制限（アプリ単位） | `config/loop-limits.yaml` のバックオフに従いリトライ。
頻発する場合は `system-healthcheck` の `content_publishing_limit` 確認を促す |
| 9 | ユーザーレベルのレート制限 | 同上。24時間以内の投稿数を確認する |
| 100 | パラメータ不正（media_url到達不可・非対応フォーマット等） | リトライしても無駄。
R2の公開URLが本当に到達可能か（`curl -I`相当）を確認してから再実行 |
| 2207026 | メディア処理失敗（動画コーデック・尺不正など） | リールの解像度・尺（10〜20秒）・
コーデック（H.264+AAC）を確認。`assemble_video.py` の出力を見直す |
| 36003 | キャプションが長すぎる/絵文字不正 | `caption-writer` にキャプション短縮を指示して
再生成（`config/loop-limits.yaml` の `caption_evaluation` ループで処理） |
| status_code=ERROR（コンテナポーリング時） | 動画処理自体が失敗 | media_urlの到達性、
動画フォーマットを確認。リトライしても改善しないことが多い |
| 9007（error_subcode 2207027, "Media ID is not available"） | **画像投稿でも発生する一時的エラー**。
コンテナ作成直後、画像側の処理がまだ終わっていない状態でpublishした場合に起きる | 一時的エラーなので
リトライで解消する（Phase 0のテスト投稿で実際に1回発生し、`with_retries()`のリトライで成功した実績あり）。
リールのポーリングと違い、画像は「即publish」設計のため、まれにこの早すぎるpublishが起きる |

## 判断の基本方針

- **code=190（トークン失効）はリトライしない**。`ig_post.py` の `with_retries()` も
  この場合は即座に諦めてエラーを返す実装になっている
- **一時的なエラー（4, 9等）は指数バックオフでリトライ**（`config/loop-limits.yaml` の
  `ig_publish_retry`: 最大3回）
- **パラメータ不正（100等）はリトライしても無駄**。原因（URL到達性・フォーマット）を
  直してから再実行する
- どの経路でも最終的に解決しない場合は「投稿しない」に倒し、`notify.py failure` で
  ステージ名・エラーコード・生成物の退避先を通知する
