# Instagram 自動投稿キット（カルーセル＋リール）

自分で書いた文章を置いておくと、その1節を根拠にして、図解カルーセルと解説リールを作り、
品質チェックを通ったものだけを Instagram に投稿するキットです。Mac の上で Claude Code が
司令塔として動き、ネタ選び・構成・評価・投稿・記録・Discord 通知までを1回の起動で済ませます。

発信の中身を決めるのは `config/brand.yaml`（誰に・何を・どんなトーンで）と、
`content/sources/` に置く自分の文章だけです。スクリプトやエージェントの定義は触らずに、
別のジャンルのアカウントへそのまま使えます。

| 作るもの | 中身 | 既定の頻度 |
|---|---|---|
| カルーセル | 図解スライド3〜6枚（4:5）。文字は Pillow で直接描くので誤字が出ない | 月・水・金 9:00 |
| リール | 縦型動画10〜20秒（9:16）。映像は Grok、ナレーションは Fish Audio、BGM は手持ちの音源 | 火・土 12:00 |
| 週次点検 | トークン期限・投稿の抜け・ネタの残り・生成物の抜き取り検査を Discord に報告 | 日 10:00 |

リールの見た目は2種類あります。`minimal` は3色のフラットな文字アニメーション、`realistic` は
実写風の手元映像に縁取りの文字を重ねたものです。はじめは `minimal` だけで運用してください
（理由は「realistic を使う前に」）。作例は `examples/` にあります。

---

## 始める前に知っておいてほしいこと

ダウンロードしてすぐ動く種類の道具ではありません。以下は、あるアカウントで実際に運用して得た数字です。

**投稿前の品質チェックで、かなりの回が中止されます。** 生成物は毎回、評価専用のエージェント（evaluator）が
合否を判定します。不合格なら該当箇所だけ作り直し、2回で通らなければ投稿せずに中止して Discord に知らせます。
「変な投稿が出るくらいなら出さない」側に倒した設計です。実績は次のとおりでした。

| | 自動実行の回数 | 投稿に至った回数 | 1回あたりの Claude 利用量（定価換算） |
|---|---|---|---|
| カルーセル | 6 | 5 | 平均 $4.1（$3.3〜5.4） |
| リール minimal | 7 | 2 | 平均 $3.8（$1.4〜6.7） |
| リール realistic | 2 | 1 | 平均 $6.3（$5.6〜7.0） |

リール minimal の 2/7 には、台本の機械検査（lint）を入れる前の失敗5回が含まれます。入れたあとは3回中2回が
投稿に至りました。中止された回も、`output/` に残った素材を手で直せば投稿できます（手順は `docs/SETUP-GUIDE.md` の12節）。

**費用は1回ごとにかかり、中止した回にも同じだけかかります。** 上の金額は Claude Code の利用量を
API の定価で換算したものです。サブスクリプションで使っている場合は請求額ではなく利用枠の消費にあたります。
ほかに、Grok（SuperGrok か X Premium+ のサブスク）、Fish Audio（ナレーションの文字数に応じた従量課金）、
Cloudflare R2（投稿のたびに消すので、保存量はほぼゼロ）が要ります。既定のスケジュール（週5本）で月 $80〜100 相当が目安です。
いきなり毎日にせず、少ない回数で始めてください。

**Instagram の API 設定がいちばんの山です。** プロアカウントにして、Meta for Developers でアプリを作り、
「Instagram業務用ログイン」で長期アクセストークンを取る、という手順が要ります。詰まりやすい箇所と
抜け方は `docs/SETUP-GUIDE.md` の8節に書いてあります。Facebook ページは要りません。

**常時起動の Mac が要ります。** 定期実行は macOS の launchd を使います。予定の時刻に Mac がスリープしていると、
ジョブはスリープから復帰した時点で遅れて実行されます（電源が切れていた場合は実行されません）。決めた時刻に
投稿したいなら、その時刻にスリープしない設定にしてください。Windows と Linux では定期実行の部分を cron などに
置き換える必要があります。

**投稿の責任は運用する人にあります。** 無人で公開投稿をする仕組みです。品質チェックは入れてありますが
完全ではありません。最初は必ず手動で数回実行し、出てきたものを自分の目で見てから定期実行に移してください。

## 必要なもの

- macOS
- [Claude Code](https://claude.com/claude-code)（`claude` コマンドが使えること）
- Python 3.10 以上
- ffmpeg（リールを使う場合。`brew install ffmpeg`）

| サービス | 何に使うか | 必須か |
|---|---|---|
| Meta for Developers | Instagram への投稿 | 必須 |
| Cloudflare R2 | 画像・動画の一時公開。Instagram の API は公開URL上のメディアしか受け付けないので、投稿直前に置いて投稿後に消します | 必須 |
| Discord（Webhook） | 成功・失敗の通知。無人運用では、止まったことに気づけるかどうかがすべてです | 必須 |
| SuperGrok または X Premium+ | リールの映像生成（Grok CLI 経由。`grok login` でサインイン） | リールを使うときだけ |
| Fish Audio | リールのナレーション音声 | リールを使うときだけ |

カルーセルだけなら、Grok も Fish Audio も ffmpeg も要りません。

## セットアップ

各サービスの画面操作まで含めた詳しい手順は `docs/SETUP-GUIDE.md` にあります。ここは全体の流れです。

### 1. 展開して依存関係を入れる

```bash
unzip insta-autopost-kit.zip && cd insta-autopost-kit
```

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
```

フォルダ名と置き場所は自由です。アカウントごとに別の場所へ展開すれば、同じ Mac で複数アカウントぶんを動かせます。

### 2. キーを設定する

```bash
cp env.template .env
```

`.env` を開いて値を埋めます。キーの取得は自分でブラウザから行ってください。値を AI に読ませたり、
チャットに貼ったりしないでください。リールを使うなら Grok CLI も入れてサインインします。

```bash
curl -fsSL https://x.ai/cli.sh | bash
```

```bash
grok login
```

### 3. アカウントの設定と、ネタ元の文章を用意する

このフォルダで Claude Code を開き、次のように頼みます。

```
brand-setup スキルで設定して。発信したいのは〇〇で、売りたいのは△△
```

対話で質問に答えていくと、`config/brand.yaml` が埋まり、投稿の根拠になる文章
（`content/sources/*.md`）の最初の数本も一緒に作れます。このとき Claude Code が
「このフォルダを信頼しますか」と聞いてくるので承認してください（5で効いてきます）。

`config/brand.yaml` に雛形のままの値（`（…）` や `@your_account`）が1つでも残っていると、パイプラインは
起動の時点で止まり、投稿スクリプトも Instagram の API を呼びません。投稿の直前には、`.env` のトークンが
`brand.yaml` の `account.handle` と同じアカウントのものかも確かめます。受け取ったままの設定や、別アカウントの
キーのまま無人投稿してしまう事故を防ぐための仕掛けです。設定が済んだかは次で確認できます。

```bash
python3 .claude/skills/shared/scripts/check_brand.py
```

### 4. 手動で1回ずつ試す

```bash
bash bin/run_banner.sh
```

```bash
bash bin/run_reel.sh
```

カルーセルは10〜20分、リールは20〜40分かかります。成功すると実際に投稿され、Discord に通知が届きます。生成物は
`output/<日付>_<テーマ>/` に残るので、Instagram 上の見え方とあわせて、トーンと見た目が意図どおりか
確認してください。ずれていたら `brand.yaml` を直してもう一度。2〜3回試して納得してから次へ進みます。

### 5. 定期実行を設定する

スケジュールは `config/schedule.yaml` に書きます。時刻と曜日を直したら登録します。

```bash
bash bin/setup_launchd.sh
```

`enabled: false` にして登録し直すと、そのジョブは解除されます。登録状況は `--status`、
すべて解除は `--unload` です。

登録の前に、次の2つを必ず済ませてください。済んでいないと初回が確実に失敗します。

- **このフォルダを Claude Code で信頼済みにする。** 3で承認していれば済んでいます。未承認だと
  `.claude/settings.json` の許可リストが丸ごと無視され、無人実行ではすべての処理が承認待ちのまま拒否されます。
  実行中の Claude にはその理由が見えないので、ログに書かれる原因の推測も外れます
- **その時刻に Mac がスリープしないようにする。** システム設定のバッテリー（またはロック画面）で設定します

## ネタ元の文章について

投稿は、`content/sources/` に置いた Markdown の1節（`## 見出し` の単位）の紹介として作られます。
画面・ナレーション・キャプションに書かれる事実は、その節に書いてあることだけです。AI が自分の知識で
話を足した場合は evaluator が不合格にします。

最初は「テーマを1行ずつ並べたネタ帳」から投稿を作らせていました。出てくるのは、どの本にも書いてある
一般論でした。自分で書いた文章を根拠として渡す形に変えてから、固有の数字・手順・資料名が入るようになりました。
ですから、ここに置く文章の質がそのまま投稿の質になります。

置くものは、ブログや note の記事、よく聞かれる質問とその答え、商品やサービスの説明、講座の台本など、
自分が内容に責任を持てる文章です。書式と注意は `content/sources/README.md` にあります。
自分のサイトの記事 HTML をそのままネタ元にすることもできます（`brand.yaml` の `content_sources.html`）。

同じ節は、ほかに選べる節があるかぎり14日間は再登場しません（選べる節が尽きると、いちばん古く使った節から
再利用されます）。週の投稿数の2倍以上の節があると、繰り返しを避けられます。
選べる節が1週間ぶんを切ると、週次点検が Discord で知らせます。補充は、文章を足すだけです。

効果効能・価格・まだ決まっていない制度など、書き方に縛りがある話題は、`brand.yaml` の
`content_sources.cautions` に語句と注意書きを登録しておきます。その語が出てくる節にだけ注意が付き、
構成・台本・キャプション・評価の全員に伝わります。

## 運用

**Discord の通知を見る。** 成功なら投稿URL、中止なら「どの段階で・なぜ」が届きます。中止が続くときは、
`output/` に残った生成物と `logs/launchd/` のログを見れば原因が分かります。多いのは、
ネタ元の文章が薄い（根拠にできる具体が少ない）、トーンの設定と文章の噛み合わせが悪い、の2つです。

**中止されたリールは手で直せます。** パイプライン全体を回し直すと費用が毎回まるごとかかります。
台本（`video_prompt_N.txt`）の該当ショットを直し、そのセグメントだけ再生成し、ナレーションは流用する、
という直し方なら追加の費用はほとんどかかりません。手順とよくある崩れ方は `docs/SETUP-GUIDE.md` の12節です。
台本を直すときの原則は1つで、**禁止を足さず、要素を減らす**ことです。動画生成モデルは否定した語を描く傾向があり、
「二重線にするな」と書くと二重線が出ます。位置と個数を肯定形で一意に書いてください。

**アクセストークンは60日で切れます。** 週次点検が期限の10日前から自動で更新を試み、結果を Discord に報告します。
更新に失敗した通知が来たら、手で更新します。

```bash
python3 .claude/skills/instagram-publishing/scripts/refresh_token.py
```

週次点検を止めると、この自動更新も止まります。止めないでください。

**見た目や判定基準を変えたいとき。** 色は `brand.yaml` の `design.palette`、声は `.env` の
`FISH_AUDIO_VOICE_ID`、語り口は `brand.yaml` の `voice.style` です。評価の基準は `.claude/agents/evaluator.md`、
スライドの文字量の上限は `.claude/skills/banner-production/references/carousel-spec.md` にあります。
文字量の上限は余白の広さと直結しているので、緩めるときは慎重に。カルーセルは Pillow で描いているので、
見た目を変えるときはプロンプトではなく `render_slides.py` の数値を直します。

## realistic を使う前に

`realistic` は実写風の人物（手元）を生成します。見た目の訴求力は強い一方で、注意が2つあります。

1つ目は顔です。「後ろ姿のみ」と指示しても顔が描かれた実測があります。そのため台本は「人物は手と前腕のみ」を
必須にしてあり、欠けていれば機械検査が生成前に止めます。さらに realistic 便（`bin/run_reel_realistic.sh`）は、
評価用のフレームを0.5秒間隔（20秒で約40枚）で抜き、顔が1枚でも写っていれば作り直さずに中止します。
それでも取りこぼしがゼロとは言えません。実在の誰かに見える顔を無人で公開することは取り返しがつかないので、
定期実行に入れる前に、手動で何本かまわして全フレームを自分の目で見てください。

2つ目は安定性です。20秒のリールは10秒ずつ別々に生成してつなぐため、前半と後半で机・光・小道具が変わりやすく、
そこで不合格になります。効いた対策は、全ショットを同じ机の真上からの構図にすること、小道具を1種類に絞ること、
光と机の形容を1語ずつにすること、後半に新しい物を持ち込まないことでした。真上からの構図にすると、
胴体や顔がフレームに入る余地もなくなります。

有効にするには、`config/schedule.yaml` の `reel-realistic` を `enabled: true` にして登録し直します。

## よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| 定期実行の初回だけ、すべての処理が「権限がない」で止まる | フォルダを Claude Code で信頼済みにしていない。このフォルダで `claude` を対話モードで1回起動して承認する |
| 予定の時刻に何も起きず、あとで Mac を開いた瞬間に投稿が始まる | 予定の時刻にスリープしていた。launchd は復帰した時点で遅れて実行する。その時刻にスリープしない設定にする |
| 「ネタの索引がありません」で中止される | `content/sources/` に文章が無いか、どの節も200字未満。`python3 .claude/skills/shared/scripts/build_article_index.py --check` で件数を確認する |
| エンドカードや表紙に、途中で切れた記事名が出る | タイトルが13字を超えている。front matter の `short_title` か `brand.yaml` の `content_sources.short_titles` に短い名前を登録する |
| リールの文字に傍点が付く・そのショットだけ書体が詰まる | 1行が長くて画面幅に収まっていない。1行9字以下になるように行を割る |
| リールの締めの一行に白い箱が付く・同じ行が二重に出る | 締めの一行にアクセント色を指定していると起きやすい。本文と同じ色の小さい文字にする |
| 投稿時に `code=9007` が出る | メディアの準備がまだ終わっていないだけで、失敗ではない。スクリプトが自動で再試行する |
| 週次点検が導入直後に「投稿漏れ」を報告する | 直近7日を数えるので、導入前の日や、スケジュールを増やす前の日も漏れとして数えられる。1週間たてば消える |
| 同じ Mac で2つ目のアカウントを動かしたい | キットを別の場所に展開する。ジョブ名に置き場所ごとの識別子が入り、ロックも各フォルダの中にあるので干渉しない。フォルダを移動するときは、移動前に `bash bin/setup_launchd.sh --unload` しておく |
| 「前回の投稿の後始末が終わっていない」で投稿が止まる | 投稿スクリプトは公開の前に `logs/PUBLISH_UNCONFIRMED.json` を書き、履歴に記録できたら消す。途中で処理が止まった・通信が切れて公開されたか分からない、というときにこれが残る。中の `what_to_do` に従って、Instagram を確認して記録し（公開されていなければ何もせず）、最後にファイルを消す。消すまで投稿は止まる（二重投稿を防ぐため） |

## ディレクトリ構成

```
config/brand.yaml        アカウントの人格（読者・トーン・オファー・色・ネタ元の設定）
config/schedule.yaml     定期実行のスケジュール（launchd の登録と週次点検の両方がここを読む）
config/loop-limits.yaml  やり直し回数の上限（緩めると、失敗時に費用だけがかさむ）
content/sources/         ネタ元（自分の文章を Markdown で置く）
content/articles/        ネタ元から自動で切り出された、節ごとの根拠テキスト（手で編集しない）
content/themes.md        いまある紹介ネタの一覧（自動生成。眺める用）
content/bgm/             リールの BGM 音源（自分で置く）
bin/                     手動実行・定期実行の入口
.claude/orchestrators/   司令塔（Claude Code のメインセッション）への指示書
.claude/agents/          ネタ選定・台本・キャプション・評価の各エージェント
.claude/skills/          カルーセル・リール・投稿・点検・初期設定の手順とスクリプト
docs/SETUP-GUIDE.md      各サービスの設定手順と、実際に詰まった箇所
docs/DESIGN.md           見た目の方針（余白・3色以内・1枚1メッセージ）
examples/                カルーセルの構成とリールの台本の作例
output/                  生成物（投稿1本ごとにフォルダが残る）
logs/                    投稿履歴（posted.jsonl）と実行ログ
CLAUDE.md                すべてのパイプラインに共通のルール（司令塔が毎回読む）
```

---

## 含まれていないもの

- **`.env`**: キーは含まれていません。各自で取得してください
- **BGM 音源**: 含まれていません。商用利用できる音源を `content/bgm/` に置いてください（`content/bgm/README.md`）
- **ネタ元の文章**: 書式の見本（`content/sources/_sample.md`）だけが入っています。見本は投稿には使われません
