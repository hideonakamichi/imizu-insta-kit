# slides.json 仕様（insta-reel-script-writer が生成する）

`slides.json` が画像・音声・動画すべての SOT（Single Source of Truth）。`slide_id` が
全ファイル（画像・音声）を紐づけるキーであり、配列インデックスは使わない。

参照: myuuu-io/youtube No.003 の `video-production-pipeline/SKILL.md` Stage 2 を、
30〜60秒・6〜10枚の縦型リール向けに簡略化したもの。

## 全体構造

```json
{
  "meta": {
    "video_title": "動画タイトル（内部管理用、投稿キャプションとは別）",
    "duration_estimate_sec": 45,
    "total_slides": 8
  },
  "global_prompt_suffix": "画像生成プロンプトの全スライド共通サフィックス（任意）",
  "global_negative_prompt": "全スライド共通の除外指定（任意）",
  "slides": [ ... ]
}
```

`meta.total_slides` は `slides` 配列の実際の長さと必ず一致させる（`check_consistency.py` が検証）。

## 各スライドのスキーマ

```json
{
  "slide_id": 1,
  "slide_role": "フック | 問題提起 | 説明 | 具体例 | まとめ・CTA",
  "narration_text": "TTSに渡す読み上げテキスト（後述の変換ルール適用済み、40〜120字）",
  "headline_text": "画像に焼く見出し（日本語、16字以内目安。縦型は横型よりスペースが狭い）",
  "sub_text": "画像に焼く本文テキスト（必須、30〜60字・1〜3行目安）。ナレーションの要点を要約し、無音でもスライドだけで内容が伝わるようにする",
  "prompt_for_generation": "gpt-image-2向け英文プロンプト。DESIGN.md Minimal方針に沿うこと",
  "negative_prompt": "このスライド特有の除外指定（英文、省略可）"
}
```

## narration_text の TTS変換ルール（絶対厳守）

Fish Audioに直接渡るテキスト。守らないと音声化が破綻する。

- **日本語と英数字の間に半角空白を入れない**
  - NG: 「5 つ目」「Week 19」 → OK: 「5つ目」「ウィーク19」
- **英単語は原則カタカナに開く**（固有名詞は除く）
  - NG: 「auto mode」「hooks」 → OK: 「オートモード」「フック」
- 読点「、」は除去（Fish Audioが自然に間を取る）
- 矢印記号「→」「←」は使わない
- 改行は禁止（1スライド=1行のテキスト）
- 文末は「です・ます」調。同じ文末を連続させない
- **1スライド40〜120字**（リールは1枚3〜8秒想定のため、No.003の100〜300字より短い）

## スライドだけで内容を完結させる（字幕なし設計・絶対厳守）

**このパイプラインは字幕（テロップ）を使わない**（2026-07-20の設計変更。スライド本文と
字幕の併存は縦型では視線移動が多く視聴ストレスになり、切替タイミングのズレもノイズに
なるというユーザーフィードバックによる）。したがって:

- 無音視聴が多数派のため、**`headline_text` + `sub_text` だけで各スライドの内容が
  伝わること**が必須。ナレーションでしか言っていない要点を作らない
- `sub_text` は省略不可。ナレーションの要点を30〜60字（1〜3行）に要約する
- 表示時間（1枚3〜8秒）で読み切れる文字量に抑える。詰め込みすぎは insta-evaluator が差し戻す

## prompt_for_generation の書き方

- DESIGN.md Minimal方針（3色以内・高コントラスト・全テキスト日本語）に従う
- **テキストのことは一切書かない**（2026-07-27改修）。画像モデルは**文字なしイラストのみ**を
  生成し、`headline_text` / `sub_text` は `overlay_text.py` がPILで焼き込む。
  位置・サイズ・折り返し・セーフゾーンはコードで決定論的に保証される。
  （旧方式: AIに「一字一句そのまま描画せよ」と指示 → 幅制約を確率的にしか守らず
  左右見切れが再発、2026-07-27 abort_no_post を最後に廃止）。
  プロンプトには**ビジュアル（背景・図・アイコン・配色・雰囲気）と構図**だけを書く
- 縦型（9:16、生成サイズ1024x1536）前提でレイアウトを指示する。
  `generate_slides.py` が全スライド共通で「文字なし・上45%は無地背景・下半分に
  イラスト」という構図指示を自動付加するため、重複して書く必要はない

### イラストの構図ルール（generate_slides.py が自動付加）

- **上部45%**: 無地背景のみ。テキストオーバーレイ領域として予約される
- **下部12%（約184px）**: Instagramリールのキャプション・いいね等のUIと重なるため、
  イラスト要素を置かない
- **左右各10%**: `assemble_video.py` が 1024x1536 → 1280x1920 拡大 → 中央 1080x1920
  切り出しを行うため必ずクロップされる。重要なイラスト要素は中央80%以内に収める
- テキストのセーフゾーンは overlay_text.py がコードで保証する
  （最大幅672px＝最終動画で左右各120px以上のマージン）ため、プロンプトで気にする必要はない

## 1スライドの目安尺（1.5倍速前提）

- **ナレーション音声は Step 4 で1.5倍速に加工される**（reel-production/SKILL.md参照）。
  等速の読み上げ速度は日本語で概ね1秒あたり4〜5文字なので、1.5倍速後は実効6〜7文字/秒
- 尺の計算は倍速後で行う: 合計文字数 ÷ 6.75 ≒ 完成動画の秒数。
  リール全体を30〜60秒に収めるには、**ナレーション合計220〜400字**を目安にする
  （6〜10枚構成なら1枚あたり40〜70字程度。合計が220字を下回ると30秒を割るので注意）
- 最初のスライド（slide_id: 1）は必ず「フック」役割とし、冒頭2秒で結論を言い切る

## テキストの行分割ルール（overlay_text.py の挙動を前提に書く）

- **自動折返し**は文節境界（budoux）で行われ、行長は均等化される。語中分断や
  1文字だけの孤立行はコード側で防がれる
- **明示改行 `\n` はそのまま尊重される**（再折返しは一切かからない）。行の幅が
  描画上限を超える場合はフォント全体が自動縮小される。つまり「1行だけ長い明示改行」を
  書くと全行が小さくなるので注意
- 読みやすさの目安（基準フォントサイズで収まる幅）: **headline は1行7字・最大2行**、
  **sub_text は1行12字・3行以内**。これを超えても見切れはしないが文字が小さくなる
- 折る位置に意図がある場合（キャッチコピーの区切り等）だけ `\n` を書き、
  それ以外は自動折返しに任せてよい

## headline_text の文字数制約

- 縦型は横型よりテキスト表示幅が狭いため、**16字以内**を目安にする（No.003の横型32字より厳しい）
- DESIGN.mdのテキスト圧縮8原則（具体語に圧縮・構造化記号活用・数字は意味とセット等）を適用する
