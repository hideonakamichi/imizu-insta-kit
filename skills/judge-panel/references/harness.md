# ジャッジ・ハーネス契約（正本）

judge-panel の実行契約。手順の詳細は [SKILL.md](../SKILL.md)、起動一覧は [hybrid-flow.md](hybrid-flow.md)。

**Agent 引数の正は本ファイル。** User Rule の `readonly: true` は「子に書かせない意図」であり、存在しない引数は渡さない。Claude Code では隔離が **構造的に保証されている**（下記）。

## 成功の測り方

次を満たしたら成功。文章の上手さは見ない。

- 選んだ審査員が **契約どおり止まって返った**（または欠席扱いで親が統合した）
- 子がファイルを書いていない
- 親が Go / Revise / Stop を1枚出した

## 入出力

| 向き | 中身 |
|------|------|
| 親 → 子 | 評価対象の全文または抜粋、`[judge:REVIEW-ONLY:<ID>]`、編集禁止（**ルーブリックは子が自分で持つ**） |
| 子 → 親 | 良い点／悪い点／改善案／親が確認すべき事項／判定 のみ。**各指摘に優先度（最重要 / 高 / 中 / 低）** |
| 止める条件 | 最大5並列。下表のカウンタを超えたら止める |

## 隔離（Claude Code では構造で保証される）

`agents/<ID>.md` の `tools:` に書いたツールしか、その子は使えない。**`Write` / `Edit` を与えていないので、子は物理的にファイルを書けない。** Cursor 時代のようにプロンプトだけで抑える必要はなくなった。`readonly` という引数はどちらの環境にも存在しない。

親が守ること:

1. プロンプト先頭に **編集・探索・実装禁止** を入れる（二重の歯止め）
2. 定義ファイルの `tools:` に `Write` / `Edit` を **足さない**
3. 子の出力がフォーマット外（規定の見出し以外、または編集手順）なら捨てて欠席扱い
4. **優先度が付いていない出力は形式崩れ**として扱う（再試行1回 → 欠席）

`bugbot` と `security-review` だけは `Bash` を持つ。差分取得とテスト実行のためで、**書き込み・`git commit`・`git push`・`rm` は定義ファイルで禁止している。**

## ツールの別名（環境が違っても止めない）

| 役割 | Cursor での名前 | 無いときの代替（1段だけ） |
|------|-----------------|---------------------------|
| レビュー子プロセス | `Agent`（Cursor では `Task`） | 親が同じルーブリックで順に審査する（並列しない） |
| 質問UI | `AskUserQuestion`（Cursor では `AskQuestion`） | チャットに A〜E を出し、1問だけ待つ |
| コードバグ審査 | `bugbot` | 無いならコード・ジャッジは Stop と書いて止める |
| セキュリティ審査 | `security-review` | 同上 |

無いツールを無理に呼ばない。代替も無ければ **Stop** と理由を書く。

## 並列とコスト

| 項目 | 値 |
|------|-----|
| デフォルト | 対象に応じた **1〜2**（hybrid-flow の「軽く」に近い） |
| 上限 | **5**（フル／ユーザー明示時だけ） |

## 2つのカウンタ（混ぜない）

| 名前 | 何を数えるか | 上限 | 超えたら |
|------|--------------|------|----------|
| **再試行** | 起動失敗・形式崩れ | 同じ人に **1回** | **欠席**。残った人で統合 |
| **再ジャッジ** | 統合が Revise のあと、直しを見て同じ人に聞く | 案件あたり **1回** | それ以上は親が止めてユーザーに返す |

## 失敗と劣化

| 失敗 | 親の動き |
|------|----------|
| 起動できない | 再試行1回 → 欠席 |
| 形式崩れ（判定が無い等） | 同じパケットで再試行1回 → 欠席 |
| 全員欠席 | 中断し、ユーザーに報告 |
| 子が編集した形跡 | その出力は捨てる。欠席 |

## 観測（親が残す1ブロック）

統合レポートの直前に、次を内部メモしてよい（ユーザー向けは短くてよい）。

```
起動: {ID一覧} / 並列: {n} / 再試行: {n} / 再ジャッジ: {0 or 1} / 欠席: {ID or なし}
```

## 次にできること（親向け・固定）

統合の判定に従う。Go なら作業続行。Revise なら親が直し、ブロッカーを出した人だけ再ジャッジ1回。Stop ならユーザーに止まった理由を返す。
