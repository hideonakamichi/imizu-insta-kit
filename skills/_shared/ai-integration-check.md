# AI 組込み確認（グリル・提案共通）

機能追加・改善・計画・提案を扱うとき、**AIを組み込むかどうかを必ず1問で確認**する。

## いつ必須か

- `grill-me`（グリル）でスコープが **プロダクト・機能・ワークフロー** に触れるとき
- 実装プランを出す前（Plan / Agent）

## 確認の3択（質問UI必須）

第一手段は AskQuestion。**無い／失敗したら** 同じ A〜E をチャットに出す（止まらない）。詳細 → `grill-me/references/question-format.md`。

**設問型は [grill-me/references/question-format.md](../grill-me/references/question-format.md) と同一。** `title` = `グリル N問目 — AI方針`。A=推奨、B/C/D=代替（B→C→Dで複雑）、E=Other…（その他・チャット）。

**AskQuestion の例（B→C→D で複雑度 UP）:**

| id | label | 複雑度 |
|----|-------|--------|
| a | B. アプリ内AI（生成→プレビュー→人が確定） — 推奨 | 推奨 |
| b | C. AIなし（手動・ルール・テンプレのみ） | 低 |
| c | A. 外付けAI（別ツールで処理→結果だけ貼る） | 中 |
| d | B+. アプリ内AI＋複数API・自動反映まで | 高 |
| （E） | Other… | その他（チャット） |

**方針の意味（記録用）:**

| 記号 | 意味 | 例 |
|------|------|-----|
| **A. 外付けAI** | 人が別ツールを使い、結果だけアプリに入れる | AI文案のコピペ |
| **B. アプリ内AI** | サーバー経由で生成。型・プレビュー・人の確定 | 生成ボタン → プレビュー |
| **C. AIなし** | ルール・UI・DB・手作業のみ | 保存・チェックだけ |

**おすすめ:** 文脈に合わせて A 番を推奨にし、`— 推奨` を付ける。

## B（アプリ内AI）を選んだとき、追加で決めること

| 任せる | 任せない |
|--------|----------|
| 文案・質問文など**中身の生成** | JSONの形・パース（zod） |
| 1パーツ／1フィールドなど**狭い範囲** | パーツ構成・必須ルール |
| 提案・下書き | **保存・反映・削除**（人またはコード） |

**最低限のハーネス:** 固定出力形式 → 検証 → プレビュー → 人が確定（自動反映は明示同意まで避ける）

## 記録

グリル終了・提案下書き前に、合意を1行で残す:

> **AI方針:** A / B / C — （一言理由）

未決のまま実装に進まない。
