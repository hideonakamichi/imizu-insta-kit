# Gemini 用スライド作成プロンプト（Step 4b 正本）

Step 4 で出力した **スライド設計図（A）** を、Google スライド／Gemini に渡す **操作プロンプト** に変換する手順正本。

- **設計図（Markdown + JSON）が SSoT。** Gemini 出力はたたき台。ズレたら材料を直してパイプライン再実行（手作業で設計を書き換えない）
- **完成 PPT の自動生成は v0 非ゴール。** 本プロンプトは Gemini が下書きを作るための入力

## いつ出すか

Step 4（スライド設計 A）の **直後・毎回・必須**。Step 5（HTML 図解 B）の前。

## 出力ファイル

| 項目 | 内容 |
|------|------|
| ファイル名 | `Geminiプロンプト_{deck.meta.title}.md` |
| 保存先 | 設計図と同じディレクトリ（例: `output/`） |
| 形式 | ユーザーが **そのままコピペ** できる1ブロック（見出し＋ fenced code 内にプロンプト本文） |

設計図ファイル名が `スライド設計_◯◯.md` なら、プロンプトは `Geminiプロンプト_◯◯.md` と対応させる。

## 生成手順（親エージェント）

1. Step 4 の `deck` JSON と Markdown 設計図を正とする
2. 下記 **プロンプトテンプレート** の `{...}` を埋める
3. `~/.cursor/rules/references/starbucks-visual.md` のパレット・レイアウトを **デザイン節** に反映（毎回同じ骨格でよい）
4. **枚一覧** を JSON `slides[]` から生成（`order`・`title`・`message` を1行ずつ）
5. **品質** → [output-quality.md](output-quality.md) の「Gemini プロンプト」節
6. チャットにも **プロンプト全文** を fenced code で提示（ファイルと同一内容）

### 埋めるプレースホルダ

| プレースホルダ | ソース |
|----------------|--------|
| `{DECK_TITLE}` | `deck.meta.title` |
| `{SLIDE_COUNT}` | `deck.slides.length` |
| `{SLIDE_LIST}` | 各 slide: `{order}. {title} — {message}` |
| `{ATTACHMENT_HINT}` | 設計図ファイル名（例: `スライド設計_週次横断進捗会.md`） |
| `{AUDIENCE}` | `deck.meta.audience` または「（未指定）」 |
| `{DURATION}` | `deck.meta.durationMinutes` または「（未指定）」 |

## プロンプトテンプレート

以下を **1ブロック** として出力する。文言は設計図に合わせて `{SLIDE_LIST}` 等だけ差し替え、**厳守・禁止・デザイン節の骨格は毎回維持**。

```text
あなたは Google スライド作成のアシスタントです。
添付のスライド設計図（{ATTACHMENT_HINT}）に従い、日本語プレゼン「{DECK_TITLE}」を **{SLIDE_COUNT}枚** 作成してください。

## 前提
- 聞き手: {AUDIENCE}
- 尺の目安: {DURATION} 分
- 設計図の Markdown と JSON が正本です。こちらの創作・改変は禁止です。

## 厳守
- 設計図の文言を **改変・追加・削除しない**（数字・期限・固有名詞もそのまま）
- **1枚1メッセージ**。1枚の箇条書きは3〜5個まで
- 各枚に設計図の **スピーカーノート** を設定する
- 「載せない（口頭のみ）」はスライド画面に載せない
- 設計図にない KPI・体験・将来目標を **創作しない**

## デザイン（スタバ風・近似でよい）
- スライド背景: #f7f7f5（オフホワイト）
- 本文・見出し: #1e1e1e
- アクセント（左ボーダー・重要数字・番号）: #006241（面積15%以内）
- カード面: #ffffff、角丸、余白多め
- フォント: Noto Sans JP または ヒラギノ角ゴ
- 情報を詰め込まない。見出し帯の全面ネイビー塗りは避け、左ボーダー＋白カード
- スターバックス公式ロゴ・固有名・公式コピーは使わない

## 枚構成（設計図 Slide 1〜{SLIDE_COUNT} に1対1対応）
{SLIDE_LIST}

各枚の「画面に載せる」「スピーカーノート」は添付設計図からそのまま使ってください。
表がある枚は設計図の表構造を維持してください。

## 出力形式
1. Google スライド上で {SLIDE_COUNT} 枚のたたき台を作成する
2. 完了後、枚ごとに **タイトル・箇条・スピーカーノート要約** を一覧でテキスト出力し、設計図と照合できるようにする
```

## ユーザーへの使い方（出力ファイル先頭に短く記載）

Markdown ファイルの **プロンプト本文の前** に、次の3行程度を書く:

1. **添付:** 同じフォルダのスライド設計図 `.md`（JSON 含む）を Gemini に添付
2. **貼付:** 下記プロンプト全文をコピーして送る
3. **推奨:** Google スライド内の Gemini（空白プレゼンから「スライドを作成」系）。gemini.google.com の場合は出力を手動で写す

## 限界（ユーザー向け注記・1行でよい）

Gemini は色・余白を完全再現しないことがある。生成後に `#006241` / `#f7f7f5` を手直しし、設計図と文言照合すること。

## やらないこと

- 設計図にない内容をプロンプトに足して「説得力を上げる」
- Gemini 出力を SSoT にして設計図を後から書き換える
- プロンプトだけ出して設計図ファイル名（`{ATTACHMENT_HINT}`）を空にする
