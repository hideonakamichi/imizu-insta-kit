# スライド設計図の品質チェック

出力前に確認する。満たさない項目は直してから渡す。

## 構成と結論

- [ ] 結論・お願いが、原稿どおり早い枚にある（隠していない）
- [ ] 最後にお願い（Yes/No）が具体的にある
- [ ] 懸念→対策を、お願いより前に先出ししている
- [ ] 成功ゲート／キー数字が、どうやって枚に表か箇条で載っている

## 1枚1メッセージ

- [ ] 各枚の「メッセージ」が1文で、他枚と役割が被っていない
- [ ] 1枚の画面箇条がおおむね3〜5個以内
- [ ] 読み上げ全文のコピペになっていない
- [ ] 山場（フック〜なぜの核）が複数枚に薄まっていない（核は1〜2枚）

## 忠実性

- [ ] 画面・ノートの数字・体験は原稿（またはユーザー追記）由来のみ
- [ ] 原稿にないKPI・将来目標を必須ゲートとして足していない
- [ ] Markdown 設計図と JSON の枚数・文言が一致している

## 尺

- [ ] 指定分に対して枚数が過大でない（目安: 分あたりおおむね1枚前後、上限は場に合わせる）
- [ ] 削るなら how / outcome から（conclusion・gate・ask は残す）

## ビジュアル（スタバ）

- [ ] 各 Slide に **ビジュアル（スタバ）** 注記がある（`~/.cursor/rules/references/starbucks-visual.md`）
- [ ] ベーシック ADS 配色（`#C5C6C7` / `#1A365D` / `#DD6B20`）を **資料用に混在させていない**

## パイプライン

- [ ] grill-me 合意が設計図に反映されている（創作なし）
- [ ] judge-panel Approve 後に A を出力している（Revise なら再出力のみ）

## Gemini プロンプト（Step 4b）

- [ ] Step 4 直後に [gemini-slides-prompt.md](gemini-slides-prompt.md) に従って C を出力している
- [ ] 枚数・枚一覧が deck JSON / 設計図 Markdown と一致している
- [ ] プロンプトに設計図にない KPI・体験・数字を足していない
- [ ] `{ATTACHMENT_HINT}`（設計図ファイル名）が空でない
- [ ] チャット提示と `Geminiプロンプト_◯◯.md` の本文が同一である
