# Ask Mode（情報整理モード）

Cursor の Ask モードに近い進め方を再現するスキル。ユーザーが情報を小分けに渡してくる間は**整理だけ**を行い、最後にまとめて実行する。往復回数が減るぶん、トークン消費も下がる。

## 起動と終了

**起動トリガー**（大文字小文字・全角半角を問わない）：
`askモード` / `ask mode` / `アスク` / `アスクモード` / `/ask-mode`

起動したら、最初の返答で必ずこう宣言する：

> 情報整理モードに入りました。実行はしません。情報を渡してください。「実行」または「まとめてやって」と言われたら、計画を出してから一括で実施します。

**終了トリガー**：`askモード解除` / `アスク解除` / `通常モード` / `終了`
終了したら「通常モードに戻りました」と一言。以降は普段どおり。

## モード中の動き

### 1. 受け取った情報は「整理」だけする

ユーザーが情報（仕様・数値・ファイルパス・変更指示など）を渡してきたら：

- **副作用のある操作をしない**。ファイルの編集・作成・削除、コマンド実行、デプロイ、外部送信は禁止。
- 読み取り（Read / Grep / Glob）は、整理に必要な最小限だけ許可。むやみにファイルを開かない。目的は「実行」ではなく「次に何をするかの一覧を正確にする」こと。
- 受け取った内容を、**running の構造化サマリー**に追記して返す。毎回サマリー全体を短く再掲する。

サマリーの型：

```
## これまでに決まったこと
- （箇条書き。理由も一言添える）

## 対象ファイル / 場所
- （絶対パス）

## 実行するタスク一覧
1. （具体的に。まだ実行はしない）
2. …

## 未確定・要確認
- （あれば。無ければ「なし」）
```

### 2. 質問は最小限

不明点があって、それが実行結果を左右するときだけ1問確認する。それ以外は質問しない。相槌や言い換えの繰り返しもしない。1つの情報に対して数行で返す。

### 3. 合図が来たら実行する

ユーザーが `実行` / `まとめてやって` / `やって` / `go` と言ったら：

1. running サマリーの「実行するタスク一覧」を、**実行計画1枚**として提示する（何をどの順で、どのファイルに）
2. ユーザーの **OK を1回** もらう
3. まとめて一括実行する。途中の細かい確認は挟まない（ただし公開・削除・外部送信など、通常モードでも確認が要る操作は従来どおり確認する）
4. 実行後、結果を報告する

## 確実性を上げたいとき

このスキルは「指示書」であって技術的な強制ではない。誤操作を物理的に止めたいときは、モード選択で**プランモード**も併用するとよい。スキルとプランモードは両立する。

## やらないこと

- モード中の先回り実行（「たぶんこうだろう」で編集を始めない）
- サマリーに書いていない作業を勝手に足すこと
- 長い説明。モード中は簡潔に保つ
