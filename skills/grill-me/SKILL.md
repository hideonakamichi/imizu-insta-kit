# Grill Me

ユーザーの計画や設計を徹底的にインタビューし、設計ツリーの各分岐を1つずつ潰して共通理解に到達する。実装には入らない。ファイルも作らない。質問して理解を深めるだけ。

## スキルの構成

```
grill-me/
├── SKILL.md
└── references/
    ├── question-format.md      … 設問フォーマット正本（毎回必須）
    └── （共有）../_shared/ai-integration-check.md … AI組込み1問
```

## 基本ルール

- **1問ずつ聞く。** まとめて質問攻めにしない
- **毎問、質問UIを1回だけ使う。** 第一手段は AskQuestion。**無い環境ではチャットに A〜E を出す**（止まらない）。形式 → [references/question-format.md](references/question-format.md)（Markdown表・番号1〜4・長文だけは禁止）
- **必ず推奨案を添える。** A 番選択肢に `— 推奨` を付ける
- **コードベースが関連する場合は、コードで分かる事は聞かない。** Read/Grep/Glob で先に調べる
- **ユーザーが考えていない箇所を掘る。** 自明な確認は省く
- **決定の依存関係を順に解く。** Aが決まらないとBが決まらない、という順序で進める

## Step 1: 入力を理解する

ユーザーが持ち込んだ計画・設計・アイデアを読む。コードベースに関連する場合は Read/Grep/Glob で現状を把握する。自分で調べて分かる事は自分で調べる。

## Step 2: 決定ツリーを洗い出す

内部的に「この計画を実装するには何を決める必要があるか」を列挙する。以下の観点をカバーする:

| 観点 | 深掘りすべき問い |
|------|----------------|
| **ゴール** | 誰が、何のために使うか。成功の定義は何か |
| **スコープ** | やる事とやらない事の境界はどこか |
| **UI/UX** | ユーザーにどう見えるか。既存UIとの整合性 |
| **データ** | 入出力、既存データ構造との関係、マイグレーションの要否 |
| **状態・同期** | 誰が真実の情報源か。競合時の扱い |
| **エッジケース** | 例外、境界条件、エラー時の振る舞い |
| **トレードオフ** | 複雑さ vs シンプルさ、速度 vs 正確さ |
| **非機能** | パフォーマンス、互換性、セキュリティ、権限 |
| **ロールアウト** | 段階的公開、フィーチャーフラグ、ロールバック |
| **AIの関与** | 何をAIに任せ、何をコード/人に残すか。外付け vs アプリ内 vs なし。ハーネス（型・プレビュー・人の確定） |

**AI組込み確認（必須）:** スコープがプロダクト・機能・ワークフローに触れるとき、Step 3 の早い段階で **必ず1問** 確認する。詳細 → `_shared/ai-integration-check.md`（置き場所は `~/.claude/skills/_shared/`。スキル内へのベタコピー禁止）

## Step 3: 1問ずつグリルする

**必ず [references/question-format.md](references/question-format.md) を読んでから、同一ターンで質問を1回出す。** AskQuestion が無ければ、同じ内容をチャットの A〜E で出す。

| 手順 | 内容 |
|------|------|
| 1 | `title` = `グリル {N}問目 — {論点}` |
| 2 | `prompt` = `1. 決めたいこと: …` ＋空行＋ `推奨: … — …` |
| 3 | `options` 4件 — **A=推奨、B/C/D=代替（B→C→Dで複雑）、E=Other…（その他・チャット）** |
| 4 | チャットには表・「1〜4で答えて」を書かない |
| 5 | 回答後 **`grill 記録` 1行** → 次問へ |

依存関係の上流から順に進める。

### 良い質問 / 悪い質問

形式の正誤 → [question-format.md](references/question-format.md) の「禁止フォーマット」。

悪い例: Markdown 表だけ・推奨なし・質問UIなし（AskQuestion もチャット5択も出さない）
良い例: question-format.md の模範 — 質問UI + `1. 決めたいこと` + A が推奨

### 進め方

- ユーザーが答えたら **`grill 記録` 1行** → 次の分岐へ（フォーマット正本参照）
- ユーザーが「わからない」と言ったら、推奨案をそのまま採用するか聞く
- 「もう十分」「ここまででいい」とユーザーが言ったら即座に終了する

## Step 4: 終了

[question-format.md](references/question-format.md) の **「グリル完了」** 見出しどおりにまとめる。計画書やファイルは作らない。

- **決まった事** — AI方針 A/B/C があれば必須
- **未決事項** — なければ「なし」
- **次のステップ候補**

ユーザーが実装・プラン化を望んだ場合に限り、その段階で plan モードや別スキルに繋ぐ。

**次にできること:** 未決が残っていれば次の1問。ユーザーが「もう十分」ならグリル完了を出す。実装に進むならユーザーが明示したときだけ。
