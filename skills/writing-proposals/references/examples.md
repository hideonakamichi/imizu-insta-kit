## 例0：定例会議の削減（上流を埋めた完成形）

Before との対比 → [writing-basics.md](writing-basics.md#上流を埋めないとどうなるかbefore)

```
【提案】報告だけの定例会議3本を隔週にして、浮いた月6時間を提案準備に充てます。ご承認をお願いします。

◎ 現状の課題
定例会議は週7本・延べ12時間。うち報告だけの3本が週3時間を占める。
直近の会議では発言者が7人中2人だった。

◎ 提案する理由
報告だけの会議は資料の前日共有で代替できる。議論のある会議は残す。

◎ リスクと対策
共有漏れを防ぐため、資料は前日17:00までに投稿するルールにする。
```

## 例1：在宅勤務を週2日に増やす

```
【提案】在宅勤務を週2日に増やすことを承認してください。来月から3か月の試験運用にしたいです。

◎ 現状の課題
通勤に往復2時間かかり、集中して作業する時間を確保しにくい。
資料作成は1人で進める作業が多く、出社の必要性が低い。

◎ 提案する理由
移動時間を作業に充てられ、締め切り前の残業を減らせる。
週2日に絞れば、対面が必要な会議や相談は出社日にまとめられる。

◎ リスクと対策
連携が滞らないよう、出社日を火・木に固定してチームで揃える。
3か月後に稼働と成果を振り返り、継続するか判断する。
```

## 例2：採用管理ツールの導入（他ツール比較あり）

```
【提案】採用管理ツールをHRtable（月額3万円）で導入したいです。
Googleスプレッドシートで管理している採用フローを移行する承認をお願いします。

◎ 現状の課題
選考状況の共有にメール往復が発生し、1件あたり平均30分かかっている。
スプレッドシートの更新漏れで、面接の重複が月2〜3件発生している。

◎ 他ツールとの比較検討
・HRtable（月額3万円）— 採用サイトとAPI連携できる
・Recruit Board（月額2万円）— API連携できないため見送り
→推奨：HRtable（連携で更新漏れと面接重複を防げる）

◎ コスト対効果
月額3万円に対し、現在の対応工数（月約20時間）を半減できる見込み。
```

## 例3：ノー残業デーの導入

```
【提案】毎週水曜日をノー残業デーにしたいです。
定時の18時退勤を原則とすることを承認していただきたいです。

◎ 現状の課題
・定時以降は集中力が落ち、同じ作業でも時間がかかる
・平均残業時間は月40時間で、その時間帯の生産性は低い

◎ 提案する理由
・終わり時間を逆算することで生産性が上がる
・残業の常態化を防ぐことで離職リスクを下げられる
・週1回から始めることでまず効果を検証できる

◎ 補足
急ぎの仕事が入った場合は例外を認め、翌日に繰り越すルールとする。
```

## 例4：口頭報告を定型メールに切り替える（自分用模範）

実戦の対話・グリル・ジャッジ（Revise→材料追加→再出力）を経た一発出し。業務改善・工数削減＋充当先・No不安への先回りの見本。

ポイント:
- 結論でお願いまで言い切る。充当先（新規事業ブレスト）まで冒頭近くで示す
- 工数は内訳付き（報告会2時間＋作成3時間＝月5時間）
- 開始時期・測り方・定型4項目・情報欠落への対策が入っている

```
【提案】週1回の口頭報告を定型メール報告に切り替えます。
1か月の試験運用をご承認ください。承認後の翌週月曜から開始します。

浮いた時間は新規事業のブレストに充てます。

◎ 現状の課題
口頭の報告会に月2時間、報告書作成に月3時間かかっている（合計月5時間）。
口頭報告は週1回30分で、待ち時間も発生している。

◎ 提案する理由
定型メールにすれば、待ち時間なく進捗を共有できると考えている。
浮いた時間は新規事業のブレストやアイデア会議に充てる。
効果は次の2点で測る。
・報告漏れ0件
・上司からの口頭確認依頼が、発生の都度カウントして週1回以下
1か月後にこの基準で継続を判断する。

◎ 進め方
承認後の翌週月曜から開始する。
毎週金曜17:00までに、次の4項目でメール報告する。
・進捗
・詰まり
・判断依頼
・翌週予定
1か月後に基準を振り返り、継続か見直しを決める。

◎ リスクと対策
情報が欠ける・把握が遅れる懸念に対し、上記4項目を固定し金曜17:00提出とする。
緊急案件はメールを待たず、口頭または電話で共有する。

ご承認の可否をご返信ください。承認後は翌週月曜から開始します。
```

## 例5：コパイロット学習アプリの試験導入（費用・測り方の見本）

実戦でジャッジ Revise 後に材料（開始時期・総額・測り方）を足して再出力した一発出し。有料ツール導入提案の見本。

ポイント:
- 冒頭でお願いまで言い切る。期間総額・開始月・測り方（自己申告）が本文にある
- 小さく可逆（リーダー1名先行 → 2週間後に拡大 → 3か月で打ち切り可）

```
【提案】2026年9月からコパイロット学習アプリを3か月試験導入します（6名・期間総額約10万円）。ご承認をお願いします。

◎ 現状の課題
業務でCopilotをほぼ使えていない。
使い方が分からず、手が止まっている状態が続いている。

◎ 提案する理由
学習アプリで基礎から揃えれば、自己流の止まりを解消できると考えている。
効果は「週1回以上、業務でCopilotを使う人」の人数で測る。
計測は週次の自己申告とする。
3か月後に6名中4名以上なら継続、未満なら見直す。

◎ 進め方と費用
2026年9月にリーダー1名のみ開始する（月額5,000円）。
2週間後に残り5名へ拡大し、6名体制にする（月額3万円）。
試験期間は3か月。期間総額は約10万円。
期間終了時に自己申告の利用率で継続を判断する。

◎ リスクと対策
学習時間が業務を圧迫する懸念に対し、必修は短時間コースに限定する。
効果が薄い場合は3か月で打ち切り、追加費用を発生させない。
```
